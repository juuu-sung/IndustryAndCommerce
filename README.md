# 발전소 NOx 예측 및 LLM 기반 대기오염 관리 시스템

발전소의 NOx 농도 변화를 운전 데이터와 함께 살펴보고, 예측 결과를 사용자가 이해할 수 있는 관리정보로 연결하기 위해 개발했습니다. 흩어진 배출·발전·연료·기상 자료를 통합해 **월별 NOx 농도(ppm) 예측**부터 **Flask API·Gemini 설명 응답 처리**까지 하나의 흐름으로 구현했습니다.

**기간** 2025.06–07 공모전 · 2026.09–10 고도화\
**담당** 데이터 통합·특징 설계 · 모델 개발·평가 · 백엔드·LLM 연동\
**기술** Python · Pandas · Scikit-learn · XGBoost · LightGBM · Flask · Gemini

## 프로젝트의 강점

- **산업 데이터 통합:** 일별·월별·시간별 자료를 호기·월 기준으로 연결하고, 단위·출처·결측을 관리했습니다.
- **비교 근거가 있는 모델 개선:** 같은 평가 자료에서 모델·변수·로그 변환을 비교하고, 시간 순서와 발전소별 오차를 함께 확인했습니다.
- **모델을 서비스로 연결:** 전처리·예측·설명·JSON 반환을 연결하고, LLM 오류 시에도 예측값을 반환하도록 구현했습니다.

## 사용 데이터

**분당·삼천포·여수·영동·영흥 5개 발전소**의 2023년 1월~2026년 8월 자료입니다. **22개 발전소·호기 조합 × 44개월 = 968행**으로 통합했습니다.

![원천 자료를 발전소·호기·월 단위로 통합하고 모델 입력과 정답으로 구성하는 과정](docs/images/data_pipeline.png)

| 구성 | 내용 | 역할 |
| --- | --- | --- |
| 식별키 | 발전소 · 호기 · 월 | 1행은 한 호기의 한 달 |
| 입력 X | 발전 실적·연료·기상 + 과거 NOx·운전 패턴·계절성 | 후보별 변수 묶음을 비교 |
| 정답 y | 해당 월 NOx 농도(ppm) | 관측 936행 · 결측 32행(학습·평가 제외) |

*월 총배출량 kg이 아닌 일별 농도의 월 산술평균을 연구 타깃으로 사용합니다. 영동 시간별 발전 자료 11,664개를 보완했으며, [변수·단위·결합 기준](docs/DATA_QUALITY.md#통합-테이블과-모델-입력)은 별도로 정리했습니다.*

## 예측 모델

- **특징 설계:** 전월 NOx, 직전 3개월 평균, 연료 소비 변화율, 발전량 대비 연료 소비, 월별 계절성을 구성했습니다.
- **모델·검증:** XGBoost·LightGBM 회귀 모델과 앙상블 가중치를 비교했습니다. 과거 학습 → 검증 선정 → 이후 평가의 3개 구간에서 변수 묶음·로그 변환을 점검해 **기상 제외·로그 LightGBM**을 개선 후보로 선정했습니다.

## 주요 성과

**전월 값 예측 대비 RMSE 35.7% 감소 — 34.67 → 22.28 ppm**

![동일한 370개 관측에서의 모델별 RMSE·MAE 비교](docs/images/model_performance.png)

*2024년 하반기~2025년의 동일한 기존 호기·월 370건에서 비교한 개발 결과입니다. 평가 기간을 반복 활용했으며, 급등 구간의 오차가 남아 후보의 서비스 적용은 보류했습니다.*

## 핵심 문제 해결

| 상황 | 문제 | 행동 | 해결한 것 |
| --- | --- | --- | --- |
| NOx·발전·연료·기상이 서로 다른 파일·주기로 제공됨 | 집계 기준과 단위가 달라 그대로 결합하기 어려움 | 호기·월 키로 통합, ppm 타깃 정의, 연료 ton·kL 분리 | **968행의 공통 분석 테이블** 구성 |
| 일부 월 관측이 누락되고 입력에 결측이 있음 | 전월 계산 오류와 미래 정보 유입 위험 | 달력 월로 전월·3개월 평균 생성, 학습 구간 중앙값으로 보완 | **시간 순서를 지키는 특징·결측 처리** 구현 |
| 기간과 발전소에 따라 모델 성능이 달라짐 | 한 번의 분할이나 전체 오차만으로 모델을 선정하기 어려움 | 3개 기간·발전소별 평가, 기준선·변수 묶음·로그 학습 비교 | 개선 후보 **RMSE 22.28 / MAE 6.48 ppm**; 지역별 악화도 확인 |
| ML 예측을 LLM 설명과 API 응답으로 연결함 | 수치·자연어의 형식 차이와 외부 호출·JSON 오류 처리 필요 | 입력 검증 → 예측 → Gemini 호출 → 응답 검증, 실패 시 기본 설명 반환 | **예측 수치와 단위를 유지하는 JSON 응답** 구성 |

*급등 원인 해결과 독립 최종 성능 검증은 아직 남아 있습니다. 후보 선정과 서비스 적용을 구분했습니다.*
