# 데이터, 타깃 정의와 품질 관리

## 현재 데이터 범위

| 자료 | 단위·수준 | 반영 범위 | 주의점 |
| --- | --- | --- | --- |
| NOx 관측 | 일별 굴뚝 농도, 제공기관 농도 표기에 근거한 ppm | 2023년~2026년 8월 | 원시 구간·산소 보정·유효 플래그 미확보 |
| 발전 실적 | 호기·월, MWh, MW, %, 효율 | 같은 기간 | 발전 실적 확정 시각·공표 지연 미검증 |
| 연료 | 사업소·월 또는 영동 호기·월 | 같은 기간 | 유류 kL, 그 외 ton을 구분; 추정 배분과 실제 호기 값 구분 |
| 기상 | 사업소 관측 일자료→월 특징 | 같은 기간 | 2025년 결측이 집중된 지역 있음 |
| 시간별 발전 | 영동 호기·시간, 제공 원본 값 | 2023년 이후 수집·일부 격리, 2026년 1~8월 보완 | 전기 발전 패턴이며 SCR 운전 상태가 아님 |

최신 자료 묶음은 **968개 호기·월, NOx 관측 타깃 936개, 결측 32개**입니다. 원래 2023~2024년 묶음은 528개 호기·월, 관측 504개입니다. 관측이 없는 월은 타깃 0으로 채우지 않습니다.

영동 2026년 1~8월 시간별 자료 **11,664개 시간 셀**을 추가했습니다. 16개 호기·월, 486개 호기·일이며 정상 형식·시간 충족·월 실적 대조를 확인했습니다. 그보다 앞선 일부 운전 자료는 월 실적과 일치하지 않아 특징을 격리하고 NOx 관측값을 유지했습니다. 출력 단위 해석과 원천 계측 정의에는 추가 확인이 필요합니다.

2026년 9월 수집 점검에서는 연구 대상 전체 호기의 발전 자료가 완성되지 않았고, 새 미사용 NOx 타깃도 확보하지 못했습니다. 따라서 새 기간의 최종 평가를 완료했다는 주장은 하지 않습니다.

## 통합 테이블과 모델 입력

![원천 자료에서 호기·월 통합 테이블을 구성하는 과정](images/data_pipeline.png)

**1행은 한 발전소의 한 호기에 대한 한 달**입니다. 식별키는 `plant`, `unit`, `month`이며, 5개 발전소·22개 발전소/호기 조합·44개월로 총 968행입니다. 이 세 키의 중복은 0건입니다.

발전 실적을 기준 테이블로 삼고 NOx·연료를 발전소/호기/월 키로 연결합니다. 기상은 발전소/월 키로 연결해 같은 발전소의 호기에 공통 외기 조건을 제공합니다. 원천 자료에 없는 값은 결측으로 남깁니다.

| 구분 | 대표 변수 | 단위·구성 | 목적 |
| --- | --- | --- | --- |
| 월 운전 | `capacity_mw`, `generation_mwh`, `thermal_efficiency_pct`, `utilization_pct` | MW, MWh, %, % | 설비 규모·발전 실적·효율·이용률 |
| 연료 질량 | `bituminous_ton`, `anthracite_ton`, `lng_ton`, `solid_ton`, `pellet_ton` | 연료별 ton | 연료 종류별 소비량 |
| 연료 부피 | `oil_kl` | kL | 유류 소비량; 질량 연료와 합산하지 않음 |
| 월 기상 | `temperature_c`, `humidity_pct`, `wind_speed_ms`, `wind_sin`, `wind_cos` | °C, %, m/s, 풍향 벡터 | 일 관측을 월 특징으로 집계 |
| 과거 NOx | `nox_lag1`, `nox_roll3`, `nox_history_count`, `nox_lag1_missing` | ppm, ppm, 관측 월 수, 결측 여부 | 전월과 직전 3개월의 관측 추세 |
| 연료 파생 | 연료별 `*_change`, `*_per_mwh` | 전월 대비 변화율, ton/MWh 또는 kL/MWh | 소비 변화·발전량 대비 소비 |
| 계절·호기 구분 | `month_sin`, `month_cos`, `plant_*`, `unit_*` | 월 순환 표현, 발전소·호기 0/1 인코딩 | 계절성과 설비 차이 |
| 선택 운전 패턴 | `gen_zero_hour_fraction`, `gen_positive_hour_cv` 등 | 영동 시간별 발전의 월 특징 8개 + 자료 유무 | 0값 비중·연속 시간·전환·변동성 실험 |
| 기상 품질 | `weather_*_coverage`, `weather_*_missing` | 변수별 유효 관측일/달력일, 월 관측 결측 여부 | 기상 결측·관측 충족률 실험 |
| 정답 | `target` | 해당 월 연구용 NOx 농도(ppm) | 학습·평가에만 사용; 해당 월 정답은 입력 X에 넣지 않음 |

전월·이동평균은 같은 발전소/호기의 **정확한 이전 달력 월**에서 생성합니다. 기상·운전 패턴 포함 여부는 실험 후보마다 다르며, 실제 모델의 열 목록과 결측 보완값은 학습 구간에서 확정합니다. 기상 제외 후보는 기상 변수를 입력에서 제외합니다.

사업소 단위 연료는 호기 발전량 비중으로 배분합니다. 최신 테이블에서 **880행은 배분 추정**, **영동 88행은 공급기관의 실제 호기·월 소비량**입니다. 영동 값은 사업소 합계와 대응을 확인한 뒤 우선 사용했습니다. 발전량 기반 배분은 실제 호기 연료 계측값과 동일하지 않습니다.

타깃이 있는 **936행**만 학습·평가 대상으로 사용하며, 타깃 결측 32행을 0이나 중앙값으로 채우지 않습니다. 입력 특징의 결측은 학습 구간 중앙값으로 보완합니다. 월 발전·연료 실적은 해당 월이 끝난 뒤 확정될 수 있으므로, 현재 결과를 월 시작 시점의 사전 예측 성능으로 해석하지 않습니다.

[공개 스키마 메타데이터](generated/data_structure.json)는 집계 규모·변수명만 포함합니다. 원천 운전값과 호기·월별 실제 관측 행은 공개하지 않습니다.

## 연구 타깃 v0

타깃 이름은 `monthly_daily_stack_mean_nox`입니다.

1. 제공된 일별 NOx를 발전소·호기·날짜로 대응합니다.
2. 같은 호기에 굴뚝 A/B 값이 있으면 날짜별 산술평균합니다.
3. 호기의 해당 월에 관측된 날짜 값을 다시 산술평균합니다.

이는 **일평균값의 월별 산술평균**이며 유량 가중 농도, 공식 월평균 또는 월 총배출량이 아닙니다. 여수의 호기 미표기 `-` 자료는 대응 근거가 없어 제외했습니다. 값 0은 정지·무효·실측 0을 구분할 플래그가 없어 임의로 삭제하지 않았습니다.

농도와 발전량이 반드시 비례하지 않습니다. 연료·연소 조건·희석·산소 보정·저감설비·측정 유효성이 농도에 영향을 줄 수 있습니다. 월 총배출량을 만들려면 같은 시간대의 농도·배출가스 유량·유효 시간·표준 상태·단위와 NOx 질량 기준의 대응이 필요합니다. 현재 자료만으로 ppm에 발전량을 곱해 kg 타깃을 만들지 않습니다.

## 구현한 품질·특징 처리

| 항목 | 처리 |
| --- | --- |
| 키·중복·형식 | 날짜·호기 대응을 검증, 충돌·중복·잘못된 구조를 검사 |
| 입력 결측 | 학습 구간 중앙값으로 보완하고 보완 특징명을 API에 반환 |
| 전월·직전 3개월 | 실제 달력 월 기준; 누락된 달을 이전 관측 행으로 대체하지 않음 |
| 계절성 | 월의 sin/cos 표현 |
| 연료 | 변화율·발전량 대비 연료를 연료별 단위로 구성 |
| 호기 연료 | 영동 공급기관 호기 값은 사업소 합계와 대조, 완전 대응 후 우선 사용 |
| 기상 | 0°C·무풍 0을 관측으로 유지, 풍향은 원형 평균, 월 관측 충족률·셀 출처 기록 |
| 운전 패턴 | 발전량 0 비중·연속 시간·0→양수 전환·양수 구간 변동·피크 비율 |
| 급등 | 검토 사유와 원시값 보존; 통계상 높다는 이유만으로 타깃 삭제하지 않음 |
| 학습 범위 | 전처리·열 선택·중앙값·가중치는 학습/선정 구간에서만 산출 |

2025년 관측 타깃 256개 중 기온 결측 78개(30.5%)가 있었으며 삼천포·여수·영동에 집중됐습니다. 관측소 대응 근거 없이 외부 관측소 자료를 섞지 않습니다. 기상 제외 후보가 유리했던 결과는 현재 자료 품질·기간의 조건 아래 얻은 결과이며, 기상 자체가 무관하다는 결론이 아닙니다.

## 대표 급등 조사

영동·삼천포의 대표 급등 4개 호기·월을 선정해 일별 분포와 상위 일자의 기여를 조사했습니다. 날짜별 계측값과 기관 요청 첨부는 로컬에서 관리하며 공개 저장소에는 포함하지 않습니다.

후보 약점은 소수 급등일이 월 타깃을 크게 올리는 구간입니다. NOx 500 초과, 산소 원본값 20 초과, 온도 원본값 60 미만과 같은 조건은 **자료 확인용 휴리스틱**이며 법적 무효 기준이 아닙니다. 특히 산소·온도의 상세 계측 단위와 집계 정의가 확인되지 않았습니다. 산소 보정 민감도·저부하·정지·교정 등은 가능한 조사 가설일 뿐 확정 원인이 아닙니다.

기관 확인용 일별 첨부 (로컬 `NOx_corrected/reports/target_validation_20261003/request_bundle/case_daily_attachment.csv`)는 대표 4개 호기·월의 186개 원본 행을 포함합니다. 현재 측정 유효 여부는 모두 `unknown`입니다. [타깃 검증 절차](TARGET_VALIDATION.md)를 통해 유효성을 확인합니다.

## 추가 확보할 자료

우선순위 1은 측정 정의입니다: NOx 보정 전·후 값, 기준 산소·측정 산소, 단위·건습 기준, 유량·표준 상태, 유효 측정 시간, 원본 상태 코드, 일평균 산식, 굴뚝↔호기 대응과 적용 기간을 요청합니다.

우선순위 2는 실제 급등을 설명할 운전 기록입니다: 보일러 기동·정지·부하, 연료 종류·성상·열량, 연소 온도·공기비, SCR 가동·입출구 농도·온도, 환원제 투입량, 촉매·우회·경보·정비 시각을 요청합니다. 기관에서 제공 가능한 최소 단위와 시간 범위를 먼저 확인합니다.

우선순위 3은 새 기간 완전 자료와 기상 출처 대응입니다. 새 기간 NOx·운전·연료의 공표 및 입수 시각을 함께 기록하고, 모델 선정 기준을 고정한 후 평가합니다.

## 파일과 출처

공개 자료는 발전사 공개 다운로드 및 공공데이터 조회 결과를 바탕으로 합니다. 실제 요청 URL·매개변수·파일 SHA-256은 로컬 자료별 `manifest.json`과 수집 영수증에 기록돼 있습니다. 원천 CSV·영수증·모델은 공개 저장소에 포함하지 않습니다. 메타데이터의 과거 로컬 경로는 수집 당시 기록이며 실행 경로로 사용하지 않습니다. 데이터의 소유권이나 새 라이선스를 선언하지 않으며 재사용 시 원 제공기관 조건을 확인해야 합니다.
